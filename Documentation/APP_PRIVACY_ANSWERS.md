# App Store 개인정보 답변 초안

제출 전 Archive에 포함된 앱과 Google SDK의 `PrivacyInfo.xcprivacy`를 다시 대조한다. 아래 답변은 Google Mobile Ads 13.8.0과 User Messaging Platform 3.1.0을 포함한 현재 빌드를 보수적으로 반영한다.

## 앱 기능 데이터

- 캘린더 제목·날짜, 리듬, 준비 항목과 설정은 기기에서만 처리한다.
- 위 데이터는 Google Mobile Ads나 외부 분석 서버로 보내지 않는다.
- 결제는 StoreKit 2가 처리하며 NudgeMate는 결제 수단 정보를 수집하지 않는다.

## 제3자 광고 SDK 데이터

App Store Connect의 데이터 수집 질문에는 **예**를 선택하고 다음 유형을 신고한다. 실제 제출 화면의 용도 선택은 Archive에 포함된 SDK Privacy Manifest와 Google의 최신 데이터 공개 문서를 기준으로 한다.

| 연결 여부 | 데이터 유형 | 현재 SDK Manifest의 용도 |
| --- | --- | --- |
| 사용자에게 연결됨 | 대략적 위치 | 제3자 광고, 개발자 광고 또는 마케팅, 분석 |
| 사용자에게 연결됨 | 기기 ID | 제3자 광고, 개발자 광고 또는 마케팅, 분석 |
| 사용자에게 연결됨 | 광고 데이터 | 제3자 광고, 개발자 광고 또는 마케팅, 분석 |
| 사용자에게 연결됨 | 제품 상호 작용 | 제3자 광고, 개발자 광고 또는 마케팅, 분석 |
| 사용자에게 연결되지 않음 | 충돌 데이터 | 분석 |
| 사용자에게 연결되지 않음 | 성능 데이터 | 제3자 광고, 개발자 광고 또는 마케팅, 분석 |
| 사용자에게 연결되지 않음 | 기타 진단 데이터 | 제3자 광고, 개발자 광고 또는 마케팅, 분석 |

UMP는 대략적 위치, 성능 데이터와 제품 상호 작용을 앱 기능 목적으로 사용자에게 연결하지 않은 상태로 별도 선언한다.

## 추적과 ATT

- **추적: 예**로 신고하고 **기기 ID**를 선택한다. Google Mobile Ads 13.8.0의 Privacy Manifest가 기기 ID의 추적 사용을 선언하기 때문이다.
- 현재 앱은 ATT 권한을 요청하지 않으며 `NSUserTrackingUsageDescription`도 포함하지 않는다. 따라서 IDFA 접근을 전제로 한 문구나 동의 메시지를 설정하지 않는다.
- Google UMP 동의 상태가 광고 요청을 허용할 때만 무료 사용자에게 광고를 요청한다. 사용자는 설정의 개인정보 선택에서 동의를 다시 변경할 수 있다.

## 광고 노출 정책

- 무료 사용자에게 Daily Recap 완료 후에만 전면 광고를 시도한다.
- 로컬 24시간 쿨다운과 AdMob의 24시간 서버 빈도 제한을 함께 적용한다.
- Pro 사용자는 동의 갱신, 광고 SDK 시작, 광고 로드와 노출을 모두 건너뛴다.

## 시스템 권한

캘린더 전체 접근은 반복 일정 분석과 사용자가 요청한 일정 저장에 사용한다. 알림 권한은 리듬, 준비 체크인, Daily Recap에 사용한다. 결제 거래는 StoreKit 2가 처리한다.
